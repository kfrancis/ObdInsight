## Implementation Notes

1. **Unknown Signals**: All unknown/undecoded signals are properly marked with `IncludeInGeneration=false` as requested, preventing them from being generated by the source generator while preserving the frame structure for future implementation.

2. **Signal Attributes**: All decoded signals include:
   - Proper bit position and length
   - Factor and offset where applicable
   - Units (kW, km/h, °C, %, rpm, etc.)
   - Min/Max value ranges
   - Descriptive documentation

3. **Data Types**: Signals use appropriate types:
   - `int` for raw values and enumerations
   - `double` for scaled/offset values
   - `bool` for single-bit flags

4. **Frame Documentation**: Each frame class includes:
   - XML summary with frame ID and purpose
   - Remarks section with additional context
   - Clear indication of CAR-CAN bus

## Known Build Issues

The project currently has pre-existing compilation errors in other frame files (BcmFrames.cs, BrakeFrames.cs, InvMcFrames.cs, HvbatFrames.cs, ObcPdFrames.cs) where properties were previously marked with `IncludeInGeneration=false` but the pattern wasn't correctly applied. These errors prevent the source generator from running.

**Solution**: The same fix pattern used in CarVcmFrames.cs should be applied to the other frame files - properties marked with `IncludeInGeneration=false` should follow the established pattern.
